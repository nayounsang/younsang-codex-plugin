# Angry Insight

`$angry-insight`는 Codex 응답에 불만을 나타내는 메시지를 분석해 같은 실수를 줄일 방법을 제안합니다.

## 훅 신뢰와 수집

수집은 기본적으로 켜져 있습니다. Codex의 `/hooks` 화면에서 플러그인의 `UserPromptSubmit` 훅을 검토하고 신뢰하면, 다음 프롬프트부터 훅이 실행되는 모든 프로젝트의 프롬프트를 로컬에 저장합니다. 별도의 스킬 호출이나 수집 설정은 필요하지 않습니다. 경로 전달과 만료 정리를 위해 `SessionStart` 훅도 검토하고 신뢰해야 합니다. Codex는 신뢰한 훅만 실행하며, 플러그인 훅 명령에 `PLUGIN_DATA`를 제공해 플러그인별 쓰기 가능 디렉터리를 지정합니다. [훅 신뢰와 이벤트 문서](https://learn.chatgpt.com/docs/hooks) · [플러그인 훅 문서](https://developers.openai.com/plugins/build/plugins)

대기열은 `PLUGIN_DATA/pending/<project-key>/` 아래 프로젝트별로 나뉩니다. `$angry-insight`는 현재 프로젝트의 항목만 조회합니다. 프로젝트 키는 프로젝트 루트 경로의 해시이며, 실제 경로는 각 이벤트 안에 보관됩니다.

이전 버전의 대기 항목은 세션 시작이나 목록 조회 때 프로젝트별 디렉터리로 옮깁니다. 이전 버전의 `settings.json`은 더 이상 수집 여부를 제어하지 않으며, `clear`를 실행하면 제거됩니다.

수집을 중지하려면 `/hooks`에서 `UserPromptSubmit` 훅을 비활성화하거나 신뢰를 해제합니다. 기존 대기 항목과 보고서는 유지됩니다. Angry Insight 데이터를 지우려면 `python3 "<helper path>" --data-dir "<data directory>" clear`를 실행합니다. 모든 프로젝트의 대기 항목과 저장 사례를 삭제하지만, 훅이 신뢰된 상태라면 이후 프롬프트 수집은 계속됩니다. Codex 대화 기록 파일은 삭제하지 않습니다.

## 분석과 보관

현재 프로젝트의 새 대기 프롬프트를 분석하려면 `$angry-insight`를 실행합니다. 스킬은 대화 기록에서 가능한 직전 Codex 응답을 찾아 프롬프트를 분류합니다. 상태 값은 `complaint` 또는 `not-complaint`입니다. 불만 사례마다 Codex, Anthropic, Hacker News, npm을 검색해 해결책을 찾습니다. 검색어에는 익명화된 사례 요약만 사용하며 프롬프트 원문과 대화 기록은 검색에 보내지 않습니다.

프롬프트 원문과 대화 기록 경로는 최대 30일 보관됩니다. 만료 정리는 세션 시작과 대기 목록 조회 때 실행하며, 30일이 지난 항목은 분석하지 않습니다. Codex가 실행 중이지 않을 때는 로컬 훅이 실행되지 않아 만료 정리도 진행되지 않습니다.

분석이 끝나면 `not-complaint` 항목을 삭제합니다. `complaint` 항목은 익명화된 요약, 확인된 실수, 권고 보고서를 원자적으로 저장한 다음 원본 프롬프트와 대화 기록 경로를 삭제합니다. 대화 기록 파일 자체는 삭제하지 않습니다. 분석에 실패하면 대기 항목은 만료될 때까지 재시도할 수 있습니다. 저장한 사례는 `PLUGIN_DATA/cases/`에 남습니다.

프롬프트 제출 훅은 대기열을 훑지 않고 이벤트 파일 하나만 씁니다. 만료 정리와 중복 세션·턴 병합은 세션 시작이나 스킬의 대기 목록 조회 때 수행합니다.

대화 기록을 분석할 수 없거나 직전 응답을 찾지 못하면 그 한계를 알리고 내용을 추측하지 않습니다. 대화 기록 형식은 안정된 Codex 훅 인터페이스가 아닙니다.

## 개인정보 보호

프롬프트와 대화 기록은 로컬 플러그인 데이터에만 저장하며, 웹 검색·외부 API·원격 데이터베이스로 보내지 않습니다. 다만 `$angry-insight`를 실행하면 분류와 요약을 위해 프롬프트 원문과 가능한 직전 응답이 현재 Codex 모델의 문맥에 포함됩니다. 사용자는 이 분석 입력을 허용했습니다. 웹 조사는 익명화된 사례 요약만 사용합니다.

훅 자체는 모델이나 네트워크를 호출하지 않습니다. 플러그인은 패키지를 설치하거나 사용자 설정, 지침, 코드를 수정하지 않습니다.
